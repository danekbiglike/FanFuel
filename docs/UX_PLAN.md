# UX_PLAN.md

## Цель UX-плана

Этот документ фиксирует структуру экранов и принципы интерфейса FanFuel. Он нужен, чтобы frontend, product и design агенты двигались в одном направлении и не превращали платформу в набор разрозненных кабинетов.

## Основные UX-принципы

- Mobile-first, но desktop должен быть полноценным.
- Интерфейс не должен выглядеть как перегруженная админка.
- Покупки и донаты должны быть максимально простыми.
- Safe deal должен объясняться человеческим языком.
- Стримерская страница должна быть красивой и кастомизируемой.
- Продавец должен быстро понимать, как создать товар и получить продажи.
- Покупатель должен понимать, сколько покупки поддержит автора.
- Никакой агрессивной рекламы.
- Партнёрство должно быть честно обозначено.
- Все пользовательские тексты идут через i18n.
- Валюта, дата, число и язык форматируются по локали.

## Основные страницы

### Главная

Задача: сразу открыть marketplace обычных цифровых товаров для покупателя. Связка с авторами остаётся отличием FanFuel, но не подменяет каталог и не превращает главную в лендинг.

Ключевые блоки:

- переключатель `Покупатель / Автор / Продавец`, покупатель по умолчанию;
- поиск или явный путь к поиску;
- общие категории цифровых товаров;
- реальные товарные карточки и редакционные направления;
- creator attribution и safe deal только в релевантном контексте;
- краткие специализированные пути во вкладках автора и продавца.

Важно: не делать главную абстрактным SaaS-лендингом, презентацией платформы или каталогом только для стримеров. С первого экрана должно быть понятно, что это marketplace цифровых товаров для обычного покупателя.

### Страница для стримеров

Ключевые сообщения:

- донаты и OBS-алерты;
- витрина товаров;
- партнёрский доход;
- прозрачность для аудитории;
- мягкая монетизация.

Основные CTA:

- создать страницу;
- посмотреть пример страницы;
- открыть Studio.

### Страница для продавцов

Ключевые сообщения:

- продажи через авторов;
- партнёрский процент за результат;
- безопасные сделки;
- Seller Lite и Seller Pro;
- аналитика.

Основные CTA:

- стать продавцом;
- создать товар;
- изучить правила категорий.

### Страница для покупателей

Ключевые сообщения:

- безопасная покупка;
- поддержка автора;
- промокоды;
- история заказов;
- споры и отзывы.

### Marketplace

Содержит:

- общий ассортимент цифровых товаров; creator/OBS assets — одно из направлений, а не весь каталог;
- категории;
- поиск;
- фильтры;
- сортировку;
- карточки товаров;
- бейджи safe deal, partner, verified seller;
- товары из creator collections, если пользователь пришёл через автора.

Карточка товара показывает:

- название;
- цену;
- валюту;
- продавца;
- рейтинг;
- формат доставки;
- safe deal status;
- долю автора, если есть attribution.

### Категория

Содержит:

- хлебные крошки;
- описание категории;
- фильтры;
- список товаров;
- предупреждение для категорий, требующих правил.

### Карточка товара

Содержит:

- медиа;
- описание;
- условия выполнения;
- состав цифрового товара;
- продавца;
- отзывы;
- safe deal объяснение;
- блок creator support, если товар открыт из витрины автора;
- CTA покупки.

### Страница стримера

Содержит:

- аватар и баннер;
- описание автора;
- донат-блок;
- donation goals;
- витрину товаров;
- подборки;
- промокоды;
- топ донатеров;
- честные пометки партнёрских товаров.

Страница должна быть кастомизируемой, но базовая структура остаётся узнаваемой.

### Донат-страница

Содержит:

- сумму;
- сообщение;
- имя отправителя;
- privacy options;
- предпросмотр alert, если возможно;
- итоговую сумму;
- статус оплаты;
- ссылку на историю/чек, если применимо после интеграции.

### Checkout

Содержит:

- товар или донат;
- итоговую сумму;
- скидку;
- комиссию, если она показывается пользователю;
- долю автора;
- provider-independent payment state;
- safe deal explanation;
- idempotency-safe submit.

### Order page

Содержит:

- статус заказа;
- статус safe deal;
- сроки действия;
- действия покупателя;
- действия продавца;
- сообщения;
- файлы;
- CTA подтверждения или спора.

### Dispute page

Содержит:

- причину спора;
- таймлайн;
- доказательства;
- сообщения сторон;
- дедлайны;
- статус арбитража;
- решение админа после завершения.

### Buyer dashboard

Основная задача: быстро найти покупки, статусы, споры и отзывы.

### Streamer Studio

Основная задача: управлять страницей автора, донатами, алертами, витриной и партнёрским доходом.

### Seller Dashboard

Основная задача: создать товар, обработать заказ, понять доход и риски.

### Admin Dashboard

Основная задача: видеть очереди действий: модерация, споры, платежи, выплаты, risk flags.

### Auth pages

Требования:

- понятные ошибки;
- тексты через i18n;
- защита от enumeration;
- email verification в будущем;
- восстановление пароля.

### Settings

Настройки делятся по ролям:

- аккаунт;
- безопасность;
- локаль;
- уведомления;
- payout details;
- seller verification;
- creator customization.

### Payouts

Показывать:

- available balance;
- frozen balance;
- pending payout;
- paid out;
- withheld;
- refunded;
- disputed;
- лимиты;
- ручную проверку.

Не использовать термин «банковский счёт» для внутреннего баланса.

### Analytics

Для MVP:

- просмотры;
- переходы;
- донаты;
- продажи;
- conversion rate;
- revenue by creator;
- revenue by product;
- refunds/disputes.

## Компоненты и состояния

Каждый критичный экран должен иметь:

- loading state;
- empty state;
- error state;
- permission denied state;
- mobile state;
- desktop state;
- audit-relevant action confirmation.

## Навигация по ролям

Один пользователь может иметь несколько ролей. Навигация должна позволять переключаться между Buyer, Studio, Seller и Admin без создания разных аккаунтов.

## Принципы текста

- Писать человеческим языком.
- Не использовать юридические обещания вроде «полная гарантия».
- Safe deal описывать как процесс удержания и подтверждения, а не как банковское хранение.
- Партнёрские товары обозначать честно.
- Ошибки должны объяснять действие, которое пользователь может сделать дальше.
