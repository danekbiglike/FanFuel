# v0.1 — Auth + Profiles

Статус: `implemented`.

Цель: создать базовую модель пользователей и публичных профилей.

Входит:

- регистрация;
- логин;
- роли `buyer`, `streamer`, `seller`, `admin`;
- профили покупателя, стримера и продавца;
- публичная страница автора;
- базовая админка для просмотра пользователей;
- начальная permission model.

Не входит:

- OAuth как обязательная функция;
- сложная KYC-верификация;
- реальные платежи;
- полноценная модерация продавцов.

Критерии готовности:

- пользователь может зарегистрироваться и войти через web UI и REST API;
- роли назначаются на backend, публичная регистрация не выдаёт `admin`;
- публичный профиль автора доступен по slug;
- админ видит список пользователей и может менять статус;
- миграция `000002_auth_profiles` применима локально и на VM.

Риски:

- неправильная модель ролей усложнит будущие права;
- слабая session/JWT policy приведёт к проблемам безопасности.

Зависимости:

- базовая БД;
- миграции;
- i18n для auth ошибок и UI.
