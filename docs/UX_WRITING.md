# UX Writing

Документ описывает голос интерфейса FanFuel и примеры текстов. Все строки ниже — примеры для словарей i18n, а не разрешение хардкодить текст в JSX.

## Голос FanFuel

FanFuel говорит:

- понятно;
- спокойно;
- уверенно;
- дружелюбно;
- без канцелярита;
- без инфобизнес-агрессии;
- без "выжми аудиторию";
- без отношения к зрителям как к ресурсу.

FanFuel не обещает юридическую или финансовую защиту без проверки. Для safe deal, выплат, налогов, возвратов и спорных категорий использовать `LEGAL_REVIEW_REQUIRED` или `PAYMENT_REVIEW`.

## Плохой и хороший тон

Плохо:

```txt
Монетизируй свою аудиторию на максимум.
```

Хорошо:

```txt
Дай зрителям больше способов поддержать твой контент.
```

Плохо:

```txt
Мы гарантируем полную безопасность сделки.
```

Хорошо:

```txt
Оплата удерживается до подтверждения выполнения или решения спора. LEGAL_REVIEW_REQUIRED.
```

Плохо:

```txt
Выжми больше продаж из фанатов.
```

Хорошо:

```txt
Предложи зрителям полезные товары и честно покажи, как покупка поддерживает автора.
```

## Кнопки

Правила:

- Глагол + объект.
- Один главный CTA в контексте.
- Не использовать давление.
- Для опасных действий писать конкретно.

Примеры:

| Контекст         | Хорошо                     | Плохо                    |
| ---------------- | -------------------------- | ------------------------ |
| Регистрация      | Создать аккаунт            | Залететь сейчас          |
| Донат            | Отправить донат            | Задонатить срочно        |
| Товар            | Купить товар               | Забрать выгоду           |
| Checkout         | Подтвердить заказ          | Всё, беру                |
| Спор             | Открыть спор               | Пожаловаться на продавца |
| Выплата          | Запросить выплату          | Вывести всё              |
| Admin блокировка | Заблокировать пользователя | Наказать                 |

## Empty States

Правила:

- Объяснить, почему пусто.
- Дать следующий шаг.
- Не шутить про деньги, споры, выплаты.

Примеры:

| Контекст       | Текст                                                                               | Действие                   |
| -------------- | ----------------------------------------------------------------------------------- | -------------------------- |
| Нет товаров    | Пока нет товаров в этой категории. Попробуйте изменить фильтры или вернуться позже. | Сбросить фильтры           |
| Новый продавец | У вас пока нет товаров. Создайте первый товар и отправьте его на модерацию.         | Создать товар              |
| Новый стример  | У вас пока нет целей. Создайте цель, чтобы зрители видели, на что идут донаты.      | Создать цель               |
| Нет покупок    | Здесь появятся ваши покупки и статусы заказов.                                      | Открыть marketplace        |
| Нет донатов    | Здесь появятся первые донаты после успешной оплаты.                                 | Открыть публичную страницу |

## Ошибки

Правила:

- Ошибка объясняет, что случилось и что делать дальше.
- Не обвинять пользователя.
- Не показывать raw provider/backend details.

Примеры:

| Контекст       | Текст                                                                    |
| -------------- | ------------------------------------------------------------------------ |
| Generic API    | Не получилось загрузить данные. Попробуйте ещё раз.                      |
| Auth           | Не получилось войти. Проверьте данные и попробуйте снова.                |
| Validation     | Проверьте поле: значение не подходит.                                    |
| Payment failed | Оплата не прошла. Вы можете попробовать снова или выбрать другой способ. |
| Forbidden      | У вас нет доступа к этому разделу. Проверьте активную роль.              |
| Widget token   | Widget token не найден. Создайте новый URL в Studio.                     |

## Безопасная сделка

Правила:

- Описывать процесс: оплата, удержание, выполнение, подтверждение, спор.
- Не использовать "гарантия", "страховка", "100% безопасно" без legal review.
- Ясно показывать сроки и действия сторон.

Примеры:

```txt
Оплата удерживается до завершения заказа. Когда продавец выполнит работу, покупатель сможет подтвердить получение или открыть спор. LEGAL_REVIEW_REQUIRED.
```

```txt
Если покупатель не отвечает в срок, заказ может быть подтверждён автоматически по правилам сделки. LEGAL_REVIEW_REQUIRED.
```

## Выплаты

Правила:

- Не обещать мгновенность.
- Объяснять available/frozen/pending.
- Не называть баланс банковским счётом.
- Показывать комиссии и сроки только после подтверждения модели.

Примеры:

```txt
Доступно к выплате: сумма, которую можно запросить сейчас.
```

```txt
Заморожено: сумма по заказам, которые ещё ждут подтверждения или проверки.
```

```txt
Выплата ожидает проверки. Обычно это занимает срок, указанный в правилах выплат. PAYMENT_REVIEW.
```

## Споры

Правила:

- Нейтральный тон.
- Сроки и доказательства понятны.
- Решение админа объясняется через факты и статус.

Примеры:

```txt
Опишите, что пошло не так, и приложите материалы, которые помогут разобраться.
```

```txt
Сейчас спор ждёт ответа продавца. Мы покажем следующий шаг, когда статус изменится.
```

```txt
Решение принято в пользу покупателя. Подробности и финансовые изменения отражены в статусе заказа. LEGAL_REVIEW_REQUIRED.
```

## Донаты

Правила:

- Быстро, тепло, без давления.
- Уважать анонимность.
- Показывать статус оплаты.

Примеры:

```txt
Отправить донат
```

```txt
Сообщение появится в истории донатов и может попасть в OBS-алерт.
```

```txt
Донат создан. Ожидаем подтверждение оплаты.
```

```txt
Спасибо, донат оплачен.
```

## Маркетплейс

Правила:

- Название, цена и продавец видны сразу.
- Условия не прятать.
- Партнёрские рекомендации помечать честно.

Примеры:

```txt
Цифровые товары для стримеров и авторов
```

```txt
Продавец выполняет заказ после оплаты. Срок и условия указаны в карточке товара.
```

```txt
Часть покупки поддержит автора, если товар открыт из его витрины.
```

## Партнёрские витрины

Правила:

- Disclosure рядом с товаром.
- Не скрывать продавца.
- Не говорить, что автор "сам продаёт" партнёрский товар, если это не так.

Примеры:

```txt
Партнёрский товар. Покупка может поддержать автора.
```

```txt
Товар продаёт продавец, указанный в карточке. Автор рекомендует его в своей витрине.
```

## Модерация

Правила:

- Причины понятны.
- Решение не звучит как личная оценка.
- Admin actions auditable.

Примеры:

```txt
Товар отправлен на проверку.
```

```txt
Товар отклонён. Причина: категория требует дополнительной проверки.
```

```txt
Пользователь заблокирован. Действие записано в audit log.
```

## Словарь нежелательных формулировок

Избегать:

- "выжми";
- "дожми";
- "монетизируй по максимуму";
- "гарантируем 100%";
- "без риска";
- "моментальная выплата";
- "банковский счёт" для внутреннего баланса;
- "фанаты как источник дохода";
- "автоматический арбитраж" как обещание.

## Checklist для агента

- Текст нужен пользователю прямо сейчас?
- Он есть в `ru` и `en` словарях?
- Он не обещает юридически непроверенное?
- Он не давит на зрителя/автора?
- Он объясняет следующий шаг?
- Он подходит для ошибки/денег/спора без шуток?
