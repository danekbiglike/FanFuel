# UI States

Стандартные состояния интерфейса FanFuel. Все тексты должны идти через i18n; примеры ниже являются UX-writing ориентирами, а не строками для JSX.

## Общие правила

- State должен отвечать: что происходит, что это значит, что делать дальше.
- Для денег, споров и выплат не использовать шутливый тон.
- Цвет не единственный носитель статуса.
- Ошибки API отображаются по `i18n_key`.
- Если состояние влияет на деньги или права, показывать next action и deadline.

## Loading

Когда показывать: первый запрос данных страницы, submit формы, обновление таблицы.

Текст: "Загружаем данные" или контекстный вариант через i18n.

Действия: disabled controls, skeleton для layout, cancel только если операция безопасно отменяется.

Компоненты: `Skeleton`, disabled `Button`, `Panel`.

Чего не делать: не показывать пустую страницу; не менять layout после загрузки резко.

## Skeleton

Когда показывать: страницы с предсказуемым layout: dashboard, product page, order page, creator page.

Текст: обычно не нужен, aria-label через i18n.

Действия: нет.

Компоненты: `Skeleton`, grid placeholders.

Чего не делать: не использовать skeleton для непредсказуемого контента с риском обмана.

## Empty

Когда показывать: список успешно загрузился, но данных нет.

Текст: объяснить пустоту и следующий шаг.

Действия: создать первый товар, сбросить фильтры, открыть marketplace, создать цель.

Компоненты: `EmptyState`, secondary `Button`.

Чего не делать: не писать "ничего нет" без next action.

## Error

Когда показывать: API/network/validation error.

Текст: человеческое описание + retry, если уместно.

Действия: повторить, изменить данные, вернуться назад, открыть support позже.

Компоненты: `Alert` tone danger, field error, toast only для non-blocking error.

Чего не делать: не показывать raw backend error, stack trace или provider payload.

## Success

Когда показывать: save/create/update выполнен.

Текст: короткое подтверждение и next step.

Действия: открыть созданный объект, продолжить настройку, вернуться к списку.

Компоненты: `Alert` success, inline status, toast для transient save.

Чего не делать: не оставлять пользователя без понимания результата.

## Warning

Когда показывать: действие возможно, но есть риск/ограничение.

Текст: спокойное предупреждение.

Действия: подтвердить, отменить, прочитать подробнее.

Компоненты: `Alert` warning, `Badge` warning.

Чего не делать: не использовать warning для обычного informative текста.

## Offline

Когда показывать: network unavailable or WS disconnected.

Текст: "Связь прервалась. Мы попробуем подключиться снова."

Действия: retry, continue read-only если данные cached.

Компоненты: `Alert` warning/info.

Чего не делать: не давать отправлять финансовые формы без подтверждённого соединения.

## Unauthorized

Когда показывать: пользователь не вошёл.

Текст: "Войдите, чтобы продолжить."

Действия: login, register, back.

Компоненты: `Alert`, login CTA.

Чего не делать: не раскрывать приватные данные страницы.

## Forbidden

Когда показывать: пользователь вошёл, но не имеет роли/permission.

Текст: "Для этого раздела нужна роль продавца/стримера/админа."

Действия: switch role, request role/onboarding, back.

Компоненты: `Alert` warning.

Чего не делать: не предлагать получить admin role публично.

## Not Found

Когда показывать: public entity не существует или hidden; private entity недоступна.

Текст: "Страница не найдена или недоступна."

Действия: home, marketplace, back.

Компоненты: `EmptyState`.

Чего не делать: не раскрывать, существует ли чужой private order.

## Maintenance

Когда показывать: planned maintenance or feature temporarily unavailable.

Текст: "Раздел временно недоступен. Мы вернём его после проверки."

Действия: back, status page later.

Компоненты: `Alert` info.

Чего не делать: не использовать для незавершённых future pages; для них нужен DO_NOT_BUILD_YET в docs, а не production page.

## Payment Pending

Когда показывать: payment created/pending/requires_action.

Текст: "Ожидаем подтверждение оплаты."

Действия: обновить статус, вернуться к заказу, открыть provider confirmation если требуется.

Компоненты: `Badge` warning/info, `OrderStatusCard`.

Чего не делать: не считать pending успешным заказом.

## Payment Failed

Когда показывать: payment failed/cancelled.

Текст: "Оплата не прошла. Деньги не были подтверждены."

Действия: попробовать снова, выбрать другой способ, вернуться к checkout.

Компоненты: `Alert` danger, `Badge` danger.

Чего не делать: не обвинять пользователя.

## Payout Pending

Когда показывать: payout request pending_review/processing.

Текст: "Выплата ожидает проверки" или "Выплата обрабатывается."

Действия: посмотреть сроки, отменить только если domain allows.

Компоненты: `Badge` warning/payout, `OrderStatusCard`.

Чего не делать: не обещать мгновенность.

## Dispute Active

Когда показывать: deal/order disputed.

Текст: "По заказу открыт спор. Следующий шаг: ..."

Действия: ответить, приложить доказательства, ждать review.

Компоненты: `Alert` warning, `DealTimeline`, `Badge` disputed.

Чего не делать: не использовать обвинительный тон.

## Moderation Pending

Когда показывать: product/seller/creator profile pending moderation.

Текст: "Материал ждёт проверки."

Действия: открыть требования, редактировать draft если разрешено.

Компоненты: `Badge` warning, `Alert` info.

Чего не делать: не обещать точное время проверки без SLA.
