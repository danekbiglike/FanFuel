# FF-0348: Зафиксировать FanFuel Aurora design direction

Статус: planned  
Версия: v0.3.5  
Приоритет: P0  
Компоненты: docs, packages/ui, apps/web, apps/admin, apps/widget

### Цель

Сделать FanFuel Aurora первым шагом `v0.3.5`: зафиксировать, какие советы из дизайн-критики принимаются, какие нет, и подготовить token/material baseline до реализации новых страниц профиля, Studio и витрины.

### Что нужно сделать

- Обновить semantic color roles: primary violet, secondary cyan, support emerald, warm/orange только для hit/warning/popular.
- Описать Aurora material rules: где glass разрешён и где запрещён.
- Зафиксировать, что Aurora — внутреннее направление, а не переименование FanFuel.
- Описать правила для light/dark, `ru/en`, long strings и mobile 320/390/768/1440.
- Подготовить visual QA checklist для текущих экранов.
- Проверить, что новые задачи `FF-0351+` ссылаются на Aurora baseline.

### Acceptance criteria

- В `docs/DESIGN_SYSTEM.md` есть явный Aurora baseline.
- `docs/THEMING.md`, `docs/UI_RULES.md`, `docs/UX_RULES.md` запрещают orange/black primary-визуал и glass-везде.
- `docs/DESIGN_AUDIT.md` фиксирует принятое и отклонённое из внешней критики.
- Нет требования копировать Apple Liquid Glass или переименовывать продукт.

### Что не делать

- Не менять production UI в этой задаче.
- Не добавлять новые маршруты.
- Не создавать arbitrary CSS/HTML skins.
- Не менять payment/safe deal обещания.

### Проверка

- `rg "FanFuel Aurora|Aurora" docs/DESIGN_SYSTEM.md docs/THEMING.md docs/UI_RULES.md docs/UX_RULES.md docs/DESIGN_AUDIT.md`.
- `git diff --check`.

### Возможные риски

- Слишком широкий visual direction может превратиться в переписывание всего UI без границ.
- Неправильная трактовка glass может ухудшить читаемость.
