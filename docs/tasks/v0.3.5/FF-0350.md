# FF-0350: Обновить текущие экраны сайта под Aurora до новых v0.3.5 страниц

Статус: partial  
Версия: v0.3.5  
Приоритет: P0  
Компоненты: apps/web, apps/admin, apps/widget, packages/ui, packages/i18n

### Цель

Сначала привести уже реализованные экраны к новой визуальной базе, чтобы профиль, Studio, витрина автора и виджеты строились сразу в правильном стиле.

### Что нужно сделать

- Обновить `/` и `/marketplace` как единую marketplace-витрину: hero, topbar, role tabs, trust/support блоки, product shelves, categories.
- Обновить product page и checkout: доверие, условия, safe deal mock copy, support signal без юридических обещаний.
- Обновить buyer/seller dashboards и order/product lists в более спокойном рабочем стиле без лишнего glass.
- Обновить `/me/profile` как временный account hub до `FF-0352`, не добавляя туда новые Studio-настройки.
- Обновить `/creators/[slug]` как public support hub в Aurora-стиле без создания новой creator store route.
- Обновить admin root и OBS widget поверх новых tokens/material rules.
- Проверить product media slots: не маскировать отсутствие медиа шумными градиентами.
- Провести visual QA `ru/en`, light/dark, 320/390/768/1440.

### Acceptance criteria

- Orange/warm не доминирует в logo, primary CTA, hero accent и бейджах одновременно.
- Marketplace не считывается как adult/betting/casino/старый skin-shop.
- Product cards имеют стабильный media slot, цену, продавца, safe deal, рейтинг/социальное доказательство и спокойный author support signal.
- Dashboard/admin экраны остаются сканируемыми и рабочими.
- Существующие маршруты и IA не меняются.
- Все новые/изменённые строки добавлены в `ru` и `en`.

### Что не делать

- Не создавать `/studio/*`, `/creators/[slug]/store` или новые `/me/*` routes в этой задаче.
- Не подключать real payments, payouts, disputes или production safe deal.
- Не делать fake products/fake analytics.
- Не добавлять произвольные CSS/HTML skins.

### Проверка

- `npm run typecheck --workspaces --if-present`.
- `npm run lint`.
- `npm run build --workspaces --if-present`.
- Browser/screenshot QA на 320/390/768/1440 в light/dark.
- `rg "[А-Яа-яЁё]" apps/web apps/admin apps/widget packages/ui` для проверки i18n.
- `git diff --check`.

### Возможные риски

- Визуальный pass затрагивает много экранов и может дать регрессии на редких viewport.
- Product media без реальных файлов может снова выглядеть как placeholder, если не задать честный fallback.
