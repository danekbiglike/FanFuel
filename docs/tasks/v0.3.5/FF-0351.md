# FF-0351: Спроектировать skin-ready дизайн и i18n-stable layouts

Статус: planned  
Версия: v0.3.5  
Приоритет: P0  
Компоненты: packages/ui, apps/web, apps/admin, apps/widget, packages/i18n

### Цель

После Aurora Refresh сделать дизайн универсальным: разные скины могут менять визуальный характер сайта, но не ломают структуру страниц, навигацию, доступность и локализацию.

### Что нужно сделать

- Описать `DesignSkinPreset` и правила выбора skin preset.
- Использовать `aurora` как первый baseline preset, а не как отдельный бренд или переименование продукта.
- Разрешить скинам менять только semantic tokens, плотность, радиусы, тени, допустимые паттерны иллюстраций и preview assets.
- Запретить произвольный CSS/HTML и изменение layout slots.
- Проверить ключевые страницы на `ru` и `en`, длинных строках, light/dark, 320/390/768/1440.
- Добавить visual QA checklist для skin regression.

### Acceptance criteria

- Скин нельзя использовать для изменения информационной архитектуры.
- Все скины имеют light/dark варианты или явно наследуют base tokens.
- Длинные строки не ломают topbar, карточки, формы и dashboard panels.
- Пользовательские тексты остаются в i18n.

### Что не делать

- Не делать drag-and-drop редактор страниц.
- Не давать пользователю произвольный CSS.
- Не добавлять page-specific hardcoded colors.
- Не возвращать orange/black как primary-визуал через skin preset.

### Проверка

- `npm run typecheck`.
- `npm run lint`.
- Visual QA matrix для base skin минимум на `ru`/`en`, light/dark и mobile.

### Возможные риски

- Скин может нарушить контраст или доступность.
- Длинные английские/русские строки могут раскрыть скрытые layout-зависимости.
