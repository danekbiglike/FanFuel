# UX-TASK-033 — удобный вход и регистрация

Версия: v0.3.5. Статус: SUPERSEDED. Приоритет: P0.
Страницы: PAGE-AUTH-LOGIN, PAGE-AUTH-REGISTER, PAGE-AUTH-NAME.
Маршруты: `/auth/login`, `/auth/register`, `/auth/name`.

## Объём

По запросу пользователя обновить UX существующей авторизации: спокойная шапка без поиска, компактная форма, переключение входа/регистрации, видимые подписи, автозаполнение, показ пароля, Caps Lock, проверка полей и доступные состояния загрузки/ошибок. На шаге имени изменить оформление, валидацию и обработку сессии; смысл имени и API сохранить.

## Критерии приёмки

- Регистрация запрашивает только email и пароль, имя остаётся отдельным шагом.
- Email сохраняется в памяти при переключении форм; пароль очищается, в URL и браузерные хранилища не записывается.
- Ошибки появляются после ухода из поля или отправки, исправление проверяется при вводе. Фокус переходит на первое неверное поле; серверная ошибка объявляется и остаётся рядом с CTA.
- Отправка защищена от повторов, значения сохраняются при ошибке. Autofill и вставка разрешены.
- Временная ошибка проверки сессии не удаляет токен; доступны повтор и явный вход в другой аккаунт.
- Существующие переходы marketplace / шаг имени / `flow=creator` сохраняются; произвольные redirect URL не принимаются.
- Light/dark, ru/en, клавиатура, reduced motion, 320/390/768/1440 px; поля от 16px, основные touch targets от 44px.
- Reset, OAuth и юридические страницы не имитируются. Email verification реализована следующей задачей UX-TASK-035.

## Исследование

Исходное решение пересмотрено по прямому запросу пользователя. Email-first развилка и подтверждение владения новым адресом реализованы в UX-TASK-035; эта задача сохранена как история промежуточного визуального улучшения.
