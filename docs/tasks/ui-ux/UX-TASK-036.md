# UX-TASK-036: закрепить marketplace-first контракт главной

Статус: implemented_local в UX-TASK-040; product review ожидается.
Актуализация 2026-09-22: реализация контракта включена в UX-TASK-040; гостевые вкладки заменяют прежнее требование вкладок для всех. Итоговый статус и проверки находятся в UX-TASK-040.
Версия: v0.3.5
Приоритет: P0
Страницы: PAGE-HOME, PAGE-MARKETPLACE

## Цель

Закрепить `/` как главную marketplace-поверхность для обычных покупателей и устранить регрессии в лендинг или каталог только для стримеров/авторов.

## Что нужно сделать

- Синхронизировать `PAGE-HOME`, `PAGE-MARKETPLACE`, tracker, flows и implementation status.
- Сделать покупательский режим начальным для каждого входа на страницу; вкладки автора и продавца оставить вторичными режимами на том же URL.
- Убрать из покупательского режима большие role-презентации, длинный platform explainer и повторяющиеся CTA.
- Показать общий ассортимент цифровых товаров; creator/OBS-товары оставить важной категорией, но не определением всего marketplace.
- Использовать только реальные API-данные и честные loading/empty/error состояния.
- Добавить regression checklist или UI smoke, который проверяет marketplace-first структуру и запрет лендингового дрейфа.
- После реализации получить явный product review владельца.

## Acceptance criteria

- `/` и `/marketplace` показывают одну marketplace-страницу без redirect.
- Покупатель выбран по умолчанию независимо от ролей аккаунта.
- В первом viewport видны поиск/путь к поиску, категории или реальные товары.
- На покупательской вкладке нет большого рассказа «для авторов», общего финального CTA и hero, занимающего экран без торговой функции.
- Каталог не описан как «товары для стримеров»; минимум одна видимая категория не зависит от creator use case.
- Вкладки автора и продавца не изменяют account roles и не подменяют каталог.
- Нет fake products, fake metrics, fake reviews, fake promocodes или fake author collections.
- Пройдены `ru/en`, light/dark, keyboard tabs, reduced motion и 320/390/768/1440; отдельно проверены loading/empty/error.

## Что не делать

- Не переписывать несвязанные IMPLEMENTED страницы.
- Не добавлять новые категории риска без legal/payment review.
- Не менять API, БД, payment или safe deal domain в рамках этой задачи.
- Не начинать общий визуальный редизайн до `UX-TASK-037`.

## Проверка

- Screenshot/browser QA по acceptance criteria.
- Доступный переключатель режимов и фокус с клавиатуры.
- Проверка данных с dev seed и пустым каталогом.
- `git diff --check`.
