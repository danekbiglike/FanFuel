# UX-TASK-042 — каталог вместо лозунгов, нарисованный выбор роли и единый Ойли

Дата: 22.09.2026. Статус: READY_FOR_REVIEW. Маршруты: `/`, `/marketplace`, `/marketplace/catalog`, гостевые вкладки автора/продавца. Версия страницы: v1.2. Основание: прямой product review владельца трёх конкретных фрагментов UX-TASK-041.

## Проблема и решение

- Четыре одинаковых прямоугольника «Сделать по-своему / Помочь с проектом…» выглядят шаблонно и описывают не товарный каталог. Заменить на компактный редакционный указатель направлений: только конкретные виды товаров, линии и типографика, без пронумерованных рекламных карточек и общих обещаний.
- Быстрая навигация должна показывать общие направления цифровой торговли: игры, программы, файлы/материалы для игр, графика/шаблоны, услуги; creator/OBS остаются отдельными направлениями. Новые broad categories не разрешают автоматически ключи, аккаунты и пополнения. Не утверждать популярность категорий на FanFuel без статистики продаж: расположение — продуктовая гипотеза.
- У выбранной гостевой вкладки — асимметричная SVG-карандашная обводка с коротким рисованием при выборе, а не стандартная линия или фон кнопки. Сохранить tablist, стрелки/Home/End, 44px+ touch area, reduced-motion/SaveData fallback, обе темы.
- Ойли показывается сразу, без отдельного секционного блока под лентой. На главной живёт один actor: единый DOM-экземпляр перемещается между семантическими якорями при смене роли. Состояние/переход к якорю выделить в небольшую инфраструктуру для будущих реакций. Сейчас не строить Tamagotchi, бесконечные анимации, слежение за пользователем или игровую экономику. Не перекрывать поиск, карточки, кнопку покупки; дать возможность скрыть и вернуть персонажа.

## Acceptance

1. Категории кликабельны и ведут к работающему фильтру, пустая категория честно показывает empty state; нововведённые broad categories не открывают публикацию запрещённых форматов.
2. Нет четырёх прежних карточек/лозунгов; в обеих темах указатель выглядит частью той же типографики, без новой коллекции плиток.
3. Обводка выбранной роли видна без анимации; при переключении рисуется заново, по клавиатуре сохраняется фокус и состояние ARIA.
4. На `/` есть только один основной Ойли; при смене роли перемещается существующий экземпляр. Нет копии в empty/error и снизу страницы. На 320/390px Ойли виден в начальной области без перекрытия поиска и кнопок.
5. `ru/en`, light/dark, reduced motion, SaveData, resize/scroll и reload не ломают положение и доступность. Тестировать на фактическом localhost и в browser smoke.

## Исследование и пределы

[Steam](https://store.steampowered.com/sitemap) явно отделяет игры, программное обеспечение и DLC; [itch.io](https://itch.io/game-assets) выделяет материалы для игр. Это подтверждает понятные типы входа в цифровой каталог, но не показывает долю продаж FanFuel. Выбор порядка требует проверки на собственных данных после запуска.
