# UX-TASK-032 — базовая регистрация и шаг имени

Версия: v0.1/v0.3.5. Статус: IMPLEMENTED locally. Приоритет: P0. Связанные страницы: PAGE-AUTH-REGISTER, PAGE-AUTH-LOGIN, PAGE-AUTH-NAME.

## Задача

Убрать выбор роли и имя платформы из окна регистрации. Регистрация принимает только email и пароль, создаёт базовый аккаунт с ролью buyer. Имя платформы задаётся следующим обязательным шагом после регистрации; пока email verification не подключена, этот шаг идёт сразу после создания аккаунта. При повторном входе незавершённый шаг не пропускается.

Имя платформы — отдельное значение: оно не занимает публичный ник, не создаёт адрес витрины и не является будущим username.

## Решение

- `/auth/register`: только email/password, без role intent и display name.
- `/auth/name`: обязательный шаг имени; сохраняет его через `PATCH /api/v1/me/profile`.
- `profiles.name_confirmed_at`: внутренний маркер завершения шага; текущему пользователю возвращается как `profile_name_confirmed_at`.
- `/auth/login`: редиректит на `/auth/name`, если маркер пуст.
- Роли автора/продавца включаются отдельными сценариями после базового аккаунта, не при регистрации.
- Миграция `000006_profile_name_setup` помечает существующие профили как завершённые, чтобы не заставлять текущих пользователей проходить шаг повторно.

## Acceptance criteria

- В регистрации нет полей роли и имени.
- После регистрации пользователь попадает на `/auth/name`.
- Вход не пропускает незаполненное имя.
- Имя платформы объяснено отдельно от ника/витрины/username.
- Тексты есть в `ru` и `en`.
- Светлая/тёмная тема и semantic tokens сохраняются.
- Backend не создаёт creator/seller profile по данным регистрации.
