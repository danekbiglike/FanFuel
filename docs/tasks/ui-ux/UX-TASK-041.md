# UX-TASK-041: точность макета и commerce foundation
Статус: implemented_local; review владельца ожидается. Версия v0.4 local/mock. Основание: прямой запрос владельца после review UX-TASK-040.

## Утверждённые решения
- Предыдущий web-дизайн не принят: исправить плотность, типографику, товарную композицию и графитную фактуру по исходному макету. Сохранить гостевые вкладки и отсутствие role-рекламы в зарегистрированной ленте.
- Настоящий рисунок Ойли допустим как компактный локальный WebP с alpha; текст, значки и подчёркивания — векторные. Системные замены почерка недостаточны: локальный лицензированный кириллический handwritten font, никаких внешних runtime-запросов.
- Авторские отчисления оплачивает продавец из выручки, цена покупателю не увеличивается. Ставка витрины строго больше ставки промокода. Конфликт двух авторов разрешает покупатель явным выбором одного; двойного начисления нет.
- Промокод поддержки работает по всему разрешённому опубликованному ассортименту и не является скидкой сам по себе. Витрина — конкретный выбранный набор товаров. Включение витрины/промо независимое.
- Пользователь разрешил реализацию storefront/promo/studio/seller и algorithms из ранее FUTURE v0.4. Реальные payout/provider подключения и запрещённые категории не включаются.

## Предметная модель
Разделять произведение/товар каталога, точный вариант и предложение продавца. Совпадение заголовков не равно идентичности. Fingerprint включает идентификатор произведения, платформу, edition, способ поставки (ключ/gift/личный аккаунт/общий аккаунт/файл/услуга), региональные ограничения, язык, срок, состав и тип лицензии. Неизвестные существенные атрибуты запрещают автоматическое объединение. Fuzzy matching только предлагает кандидатов. Категория не создаётся для каждой игры: произведения отдельны от таксономии. Импорт aliases и отдельные поля активации/использования остаются следующим этапом.
Рискованные способы представлены в модели и фильтрах, но не получают разрешение публикации без LEGAL_REVIEW_REQUIRED/PAYMENT_REVIEW_REQUIRED; shared account не разрешается существующей политикой.

## Алгоритмы и объяснимость
Строгое сравнение эквивалентных предложений, объяснимое ранжирование поиска, robust price reference с валютой/свежестью/числом независимых продавцов, исключение дубликатов и выбросов, малые выборки -> insufficient_data. Отчисления не повышают органическую релевантность. Риск-сигнал не объявляет человека мошенником. Вероятность покупки — только по достаточным наблюдениям и с неопределённостью; на cold start числового прогноза нет.
Подготовить pure domain библиотеку с примерами и тестами: identity, matching, search, price, commission/attribution, confidence, seller signals, recommendations/diversity. Неиспользуемые алгоритмы изолированы и явно помечены, без скрытого влияния на покупки.

## Страницы
- PAGE-STUDIO-COMMERCE /studio: настройки витрины, промо, подбор товаров и аналитика; IMPLEMENTED_LOCAL, v0.4 local/mock.
- PAGE-CREATOR /creators/[slug]: публичные безопасные presets, баннер/аватар, порядок и вид блоков, поддержка/донат; обновление по этому запросу.
- PAGE-SELLER /seller и editor /seller/products/new: характеристики варианта, две ставки, ориентиры цены/поддержки.
- PAGE-PRODUCT /marketplace/products/[slug]: формат получения крупно, строго сопоставимые альтернативы и прозрачный получатель/сумма поддержки.
- PAGE-CHECKOUT /checkout/[productId]: подтверждённая сервером атрибуция и неизменяемый snapshot расчёта.
Новые тексты ru/en. Чужие профили изменять нельзя. Произвольные CSS/HTML запрещены; баннер/аватар проходят существующий безопасный upload либо проверяемый безопасный формат, без SSRF.

## Проверки
Unit/property tests для денежных инвариантов, вариантов, маленьких/манипулируемых выборок, фильтров и ties. Go tests/gofmt, migration checks, frontend typecheck/lint/build, browser QA. Существующие изменения пользователя не откатывать. API/DOMAIN_MODEL/PAYMENTS/ADR обновить до реализации домена.

## Результат

Реализованы перечисленные UI/API/миграции и библиотека commerce, включая подписанные медиа и перенос поддержки через cart/saved. Проверены Go + PostgreSQL, миграции up/down/up, frontend typecheck/lint/build и оба browser smoke. Каталог не наполнен фиктивными товарами. Расчёты возвратов/резерва/рекомендаций/жалоб существуют как протестированные функции без production adapters; явная карта подключения в MARKETPLACE_ALGORITHMS.md. Product review, real providers/ledger, S3/R2, telemetry и canonical import остаются следующими этапами.
