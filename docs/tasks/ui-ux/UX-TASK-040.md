# UX-TASK-040: FanFuel — живой marketplace
Статус: implemented_local; ожидает product review и интеграционный прогон с backend. Версия: v0.3.5 / Experience. Дата решения: 2026-09-22.
Связи: UX-TASK-036, UX-TASK-037, UX-TASK-038 (ограниченный пилот).
Владелец явно утвердил направление и реализацию. Этот контракт заменяет прежнее требование трёх вкладок для всех и визуальные указания Aurora на основном web-сайте.

## Страницы и контракт
- PAGE-HOME / PAGE-MARKETPLACE, маршруты / и /marketplace: один marketplace. Гости видят доступные с клавиатуры вкладки «Покупатель / Автор / Продавец», по умолчанию покупатель. После входа — только покупательская лента, независимо от ролей.
- Проверка сессии не должна вставлять/удалять полоску над товарами: зарезервирована одинаковая высота; при проверке нейтральное состояние. Сетевой сбой не удаляет токен.
- PAGE-FOR-STREAMERS /for-streamers и PAGE-FOR-SELLERS /for-sellers: самостоятельные индексируемые объясняющие страницы, доступные через footer. Те же презентации встроены в гостевые вкладки. В шапке и покупательской ленте нет рекламных входов в эти страницы.
- PAGE-MARKETPLACE-CATALOG /marketplace/catalog и PAGE-MARKETPLACE-CATEGORY /marketplace/category/[slug]: версия v0.3.5, прежние презентационные заглушки заменяются настоящей выдачей существующего API. Query/category/sort/limit/offset, порционная загрузка, отмена устаревших ответов и повтор после ошибки. Отдельного нового endpoint нет.
- PAGE-MARKETPLACE-CATEGORIES /marketplace/categories использует ту же рабочую каталоговую поверхность с категориями из API вместо устаревших ссылок на отсутствующие категории.
- Header: канистра, каталог, заметный поиск, избранное, корзина, единый вход/регистрация или меню аккаунта. Не менять существующие права ролей.
- Поиск для знающих цель; широкие категории и реальные новинки для исследования. Creator/OBS — часть ассортимента. Никаких фиктивных товаров, рейтингов, обещаний заработка или счётчиков доверия.
- Избранное и корзина в первом web-пилоте — списки в этом браузере, доступны гостям; без обещания синхронизации. Цена и наличие проверяются через API; покупка отдельного товара через существующий checkout. Общий checkout нескольких продавцов не входит.
- Презентации объясняют действующие инструменты и отдельно подписывают будущие партнёрские механики; не обещают реальные выплаты в mock/local MVP.

## Визуальный язык и движение
Графит, тёплая светлая поверхность, лайм #cafa39 с тёмным текстом; dark theme через semantic tokens. Канистра — простой знак F, без АЗС-реализма. Крупная выразительная типографика, скруглённые элементы управления, открытая товарная сетка вместо карточек внутри карточек. Карандашные акценты дозированно.
После отказа от декоративных звездочек и стрелок не оставлять смысловые блоки визуально оборванными. Подчёркивания и контурные зарисовки должны поддерживать заголовок, выбор категории, пустое состояние или иллюстрацию отсутствующей обложки; форму рисунка связывать с типом товара. Избегать симметричного повторения и лишней графики в финансовых сценариях.
Ойли — чёрная асимметричная капля с загнутой макушкой, светлыми глазами, маленькими конечностями и лаймовым бликом. Векторный пилот с добровольной реакцией по нажатию. Не блокирует интерфейс, не оценивает траты.
Общие состояния hover/focus/pressed — 120–180 мс. Однократная декоративная зарисовка — до 650 мс при первом открытии пути за сессию, без повторения на reload. Контент виден и без JS. prefers-reduced-motion и Save-Data отключают декорации; никаких бесконечных idle-анимаций, autoplay, WebGL, тяжёлых SVG-фильтров. Финансовые страницы получают только спокойную обратную связь.

## Производительность и загрузка
- SVG для брендовых иллюстраций, без растра, внешних шрифтов и новых animation runtime.
- Фиксированное соотношение сторон товарной графики, одинаковая геометрия skeleton и карточек, место под статусы загрузки/ошибки/пустого каталога.
- Порционная кнопка «Показать ещё», без принудительной бесконечной ленты.
- Цели проверки production: CLS <= 0.1, LCP <= 2.5 с, INP <= 200 мс на p75. Это цели, а не заявленные измерения.
- Проверить 320/390/768/1440, ru/en, light/dark, keyboard, reduced motion, медленный/недоступный API; отсутствие горизонтального overflow.
- Новые UI-строки только ru/en i18n. Сохранить API, финансовый домен и серверные permissions.

## Основания и пределы выводов
- [Baymard: отложенная регистрация](https://baymard.com/research-articles/delayed-account-creation): не прерывать исследование каталога регистрацией. Это не доказательство превосходства точной надписи «Войти / Регистрация»; подпись и три вкладки — продуктовая гипотеза владельца.
- [NN/g: назначение анимации](https://www.nngroup.com/articles/animation-purpose-ux/): движение должно объяснять смену состояния и обратную связь. Характер Ойли — дизайнерская гипотеза, не обещание роста конверсии.
- [web.dev: CLS](https://web.dev/articles/optimize-cls): резервировать геометрию асинхронного контента и медиа.
- Для оценки после запуска: успешность поиска/покупки, сохранения, возвраты, раздражение от маскота; длительность сессии сама по себе не критерий успеха.

## Дальнейшая дорожная карта
1. Реализовать этот web-пилот и пройти технический/визуальный QA.
2. Пользовательский review и наблюдение реальных покупателей, авторов, продавцов; корректировать по затруднениям.
3. Отдельно: синхронизация избранного/корзины, реальные медиа товара, персонализация с явным управлением.
4. Ойли: character bible, события, добровольные мини-сцены; затем отдельный spike мини-игры.
5. World / тамагочи остаётся FUTURE: приятное возвращение без смерти, голода, штрафа за отсутствие, платной прогрессии, давления на покупки. Открытия за интересы/участие, а не обязательные траты.
6. Партнёрские витрины v0.4 и реальные платежи v0.5 идут отдельными этапами.

## Реализация и проверка

Реализованы: marketplace, поиск/категории/сортировка/пагинация, гостевые вкладки и отдельные презентации, шапка и web semantic tokens, избранное/корзина в браузере, SVG-бренд и Ойли, однократные зарисовки и reduced-motion/Save-Data. Бизнес-логика кабинетов и checkout сохранена; общий стиль и обратная связь применяются через web CSS. Это не переписывание всех внутренних экранов и не полноценная игра.

Команды: `npm run lint`, `npm run typecheck`, `npm run build -w @fanfuel/web`, `npm run test:experience -w @fanfuel/web`. Smoke требует запущенный web (`FANFUEL_TEST_URL`, по умолчанию localhost:3000); Windows использует установленный Edge, иначе Chromium из `npx playwright install chromium`; канал можно задать через `FANFUEL_BROWSER_CHANNEL`. Скриншоты сохраняются вне репозитория в temp/fanfuel-experience-qa или `FANFUEL_SCREENSHOTS`.

Браузерный прогон покрывает гостей/вход/сетевой сбой сессии, клавиатурные вкладки, локальные списки и перезагрузку, checkout URL, поиск и серверную пагинацию, 320/390/768/1440, ru/en, light/dark, reduced-motion, Save-Data, CPU ×4, отказ storage и геометрию loading/empty/error. API в этом прогоне подменён фиксированными данными исключительно внутри теста.

Ограничения: локальный API:8080 не запущен, Docker отсутствует; полноценная интеграция с БД и завершённой покупкой не проверена. Field Core Web Vitals и физический слабый телефон не измерялись. В Product API пока нет медиа: карточки честно обозначают иллюстрацию категории, не выдают её за реальную обложку товара.
